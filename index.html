FROM BUTTON CLICKS TO UNDERSTANDING

Two ways to create order.

Both algorithms move complete product records. Sorting a price never disconnects it from the product name or stock.

MERGE SORT

Divide, solve, combine.

  1. Split the list into two halves.
  2. Keep splitting until each group has one product.
  3. Compare the front products of two sorted groups.
  4. Write the next product into a temporary output buffer.
  5. Copy the merged group back and continue upward.

For ascending prices: [300, 100, 200] → split → [300] and [100, 200] → merge → [100, 200, 300].

Equal keys keep their original order, because the left product wins a tie. This implementation is stable.
mergeSort(a):
  if length(a) ≤ 1: return a
  split a into left and right
  return merge(mergeSort(left),
               mergeSort(right))
QUICK SORT

A pivot creates two sides.

  1. Choose the last product in the current group as pivot.
  2. Compare every other product with that pivot.
  3. Move qualifying products toward the front.
  4. Put the pivot at its final position.
  5. Repeat on the groups before and after the pivot.

For ascending prices, values ≤ pivot go before it; larger values go after it. Descending reverses this comparison.

Swaps may change the original order of equal keys. This Lomuto partition implementation is not stable.
quickSort(a, low, high):
  if low < high:
    p = partition(a, low, high)
    quickSort(a, low, p - 1)
    quickSort(a, p + 1, high)

n = number of products. Standard time bounds count comparisons; comparing long names also depends on string length. This teaching app additionally stores visualization snapshots, which cost up to O(n² log n) space for Merge and O(n³) for Quick in the worst case. That overhead belongs to the animation, not the standard sorting algorithm.

YOUR COLLEGE PROTOTYPE

The problem it solves.

StockStudio organizes unsorted inventory by price, stock quantity, or product name, helping users inspect products in a useful order. It also visualizes the decisions of Merge Sort and Quick Sort.

Scope: 2–24 products, one sorting field at a time, local browser storage, and CSV export. No backend, sales tracking, authentication, or multi-user synchronization.

Demo: Edit a product → select a field → choose an algorithm → step through decisions → compare counts → export the result.
